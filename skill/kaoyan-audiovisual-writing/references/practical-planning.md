# 北师大842数字媒体实务策划

## 定位

数字媒体实务策划是842的独立训练任务，不计入名词解释、简答、论述三类题，也不把小论文结构直接搬成产品方案。它可能要求设计数字产品、互动体验、内容项目、游戏机制、展览装置、传播活动或综合媒介方案，应先服从题面规定的对象和交付项。

## 实务问题卡

拿到题目后识别：

```text
考试配置：年份 / 方向 / 分值 / 字数与时间
方案类型：产品 / 服务 / 内容 / 体验 / 游戏 / 展览 / 传播
目标对象：要为谁、为哪个场景解决什么问题
命令动词：策划 / 设计 / 改造 / 推广 / 运营 / 评价
题面必答项：必须出现的模块、图示或技术
媒介与技术限定：
文化、伦理、成本或实施限制：
评价重点：创新、体验、传播、社会价值、产业可行性等
```

没有明确用户群的艺术创作或内容策划，不必为了套PRD虚构精细用户画像；但仍要说明面向的受众、使用情境或体验关系。

## 统一设计决策链

实务策划使用与论述写作同源但不同形态的四层对象：

1. **实务问题卡**：确定任务、对象、需求和限制。
2. **依据单元**：记录题面材料、用户需求、政策、案例、技术条件及来源状态。
3. **设计决策单元**：把一个需求或目标，与内容/功能、交互机制、媒介形式、实现条件、预期效果和风险绑定。
4. **方案结构**：选择必要的设计决策，组织成可执行、可体验、可说明的整体方案。

单个设计决策可按下列结构表达：

```text
目标或需求：
设计决策：
内容或功能：
用户如何使用或体验：
采用该媒介/技术的理由：
预期效果：
实施条件与风险：
```

不能只列功能名称。每项核心功能或内容都要说明它解决什么问题、如何形成体验，以及为什么适合题目规定的媒介。

## 方案生成流程

1. 拆出题面的必答项和限制，判断方案类型。
2. 定义核心问题、目标受众/参与者和发生场景。
3. 提出一句话方案概念与价值主张，避免先罗列功能。
4. 建立内容或功能架构，区分核心模块与辅助模块。
5. 描述一条核心用户旅程、交互流程或体验流程。
6. 说明视觉、声音、空间、叙事和交互如何共同服务概念。
7. 选择真正必要且可解释的技术，说明作用和可行性。
8. 按题目需要补充生产流程、运营传播、商业模式或社会价值。
9. 检查隐私、版权、算法偏差、沉迷、可访问性、安全和文化表达风险。
10. 压缩为考场可书写方案，并检查每个必答项都有明确位置。

## 建议输出结构

以下是模块池，不是每题必须全部使用：

1. **方案标题与概述**：名称、方案类型、一句话概念和核心价值。
2. **背景与问题**：真实情境、目标问题和现有方式的不足。
3. **对象与场景**：目标用户/受众、典型场景和关键需求。
4. **目标与定位**：解决什么、提供何种独特体验。
5. **内容与功能架构**：核心模块、信息关系、玩法或内容组织。
6. **核心流程**：用户旅程、业务流程、交互反馈或叙事路径。
7. **媒介与审美设计**：影像、声音、空间、界面、叙事和风格。
8. **技术与生产实现**：关键技术、团队流程、资源条件和可行性。
9. **运营、传播或产业协同**：只在题目需要时展开。
10. **风险治理与可访问性**：隐私、版权、伦理、安全和特殊人群。
11. **创新点与效果评估**：创新发生在哪里，准备如何判断方案有效。

题目要求画图时，可输出信息架构图、核心流程图或用户旅程图；不要求时，不为形式完整强行增加复杂图示。

## 两种版本

- **精简考场策划版**：严格服从题面和时间，只写决定得分的模块；表述以设计决策和因果关系为主。
- **扩展迭代版**：补充需求假设、备选方案、技术路线、运营方式、风险和评估指标，并标明考场应删减内容。

## 事实与假设

- 不编造问卷人数、市场份额、用户增长、技术效果或机构合作。
- 题面没有提供调研时，可写“基于题面可推定的需求”或明确的设计假设，不能伪装成已完成的真实调研。
- 引用案例时说明它启发了哪项设计决策，不直接复制竞品功能。
- 新技术只在能改善内容、流程或体验时使用；堆叠AI、XR、区块链等名词不构成创新。
- 动态政策、平台能力和产品数据按 [材料与事实完整性](source-integrity.md) 处理。

## 评分与批改

按以下维度给出证据化诊断：

1. 题面任务和交付项是否全部覆盖；
2. 目标对象、场景和需求是否真实一致；
3. 核心概念能否统摄内容、功能、交互和审美；
4. 关键设计决策是否形成“需求—方案—体验—效果”闭环；
5. 媒介和技术是否必要、准确、可行；
6. 内容表达、艺术体验和价值立场是否成立；
7. 创新是否来自机制或组合，而非名词包装；
8. 风险、实施条件和考场完成度是否得到处理。

批改先修复题面遗漏和方案逻辑，再调整功能与流程，最后润色名称、标题和表达。
